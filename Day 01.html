1. What is JavaScript?

Core Fundamentals

⚡ Quick Revision Notes

  • High-level & Single-Threaded: Memory is managed automatically (garbage collection). JavaScript has a single Call Stack and runs on one main execution thread.
  • Dynamically & Weakly Typed: Types are checked at runtime, and values are implicitly coerced during operations (e.g. "5" - 2 === 3).
  • JIT-Compiled: Modern engines (V8 in Chrome/Edge, SpiderMonkey in Firefox) parse code into bytecode and compile hot code into optimized machine instructions on the fly.
  • Event Loop: Offloads async tasks (timers, fetch, events) to multi-threaded browser Web APIs, scheduling their callbacks back onto the Call Stack when free.
Q1.1: What is the difference between Dynamically Typed and Weakly Typed?
Conceptual
JavaScript is both dynamically typed and weakly typed. What do these two distinct terms mean?
Reveal Answer
  • Dynamically Typed: Variable types are determined at runtime, not at compile-time. A variable can hold a number now and a string later: let x = 10; x = "hello";.
  • Weakly Typed (Loose Typing): JavaScript performs implicit type coercion when types do not match instead of throwing an error: 10 + "5" → "105" (number coerced to string), and "10" - 2 → 8 (string coerced to number).
Q1.2: How does JavaScript execute asynchronous code if the engine is strictly single-threaded?
Conceptual
Clarify how the single Call Stack coordinates with the Browser Web APIs, Callback Queue, and Event Loop.
Reveal Answer
The JavaScript engine (Call Stack) executes one statement at a time. However, the browser environment provides multi-threaded background Web APIs:
  1. Asynchronous tasks (setTimeout, fetch, DOM clicks) are delegated to browser background threads.
  2. The main Call Stack continues executing synchronous code without pausing.
  3. When the background task finishes, its callback is placed in the Callback Queue.
  4. The Event Loop waits for the Call Stack to become completely empty, then pushes the callback onto the Call Stack.
Q1.3: Asynchronous Execution Order with setTimeout 0ms
Output
What will be printed to the console in what sequence?
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
Reveal Output
A C B
console.log("A") and console.log("C") are synchronous and run on the Call Stack immediately. setTimeout(..., 0) registers its callback into the Callback Queue. The Event Loop only pulls "B" from the queue after the entire script stack has cleared.
Q1.4: Call Stack Freezing via Long Synchronous Loop
Tricky Edge Case
Will the setTimeout callback execute after exactly 100ms? Why or why not?
console.log("Start");

setTimeout(() => {
  console.log("Timer completed");
}, 100);

const start = Date.now();
while (Date.now() - start < 300) {
  // Heavy synchronous blocking task for 300ms
}

console.log("End");
Reveal Output & Explanation
Start End Timer completed
Explanation: Even though the timer finishes in the background at 100ms, the main Call Stack is occupied by the synchronous while loop until 300ms. The Event Loop cannot interrupt the running Call Stack. The callback must wait until the synchronous loop and console.log("End") finish before running (at roughly ~300ms).
Q1.5: The Typeof Minefield (null, NaN, function, undeclared)
Tricky Output
Predict the string returned by each typeof check:
console.log(typeof null);
console.log(typeof NaN);
console.log(typeof function() {});
console.log(typeof undefinedVar);
Reveal Output & Explanation

  • typeof null === "object": A historical bug in JavaScript's original implementation where object type tags were 0.

  • typeof undefinedVar === "undefined": For completely undeclared variables, typeof safely returns "undefined" without throwing.

2. Function Calls vs. Function References

Functions

⚡ Quick Revision Notes

  • Function Reference (fn): Refers to the function stored in memory. Does not execute the function. Used for callbacks and event handlers.
  • Function Call (fn()): Adding parentheses immediately invokes the function and evaluates to its return value.
  • Passing Arguments: Never write addEventListener('click', fn(arg)) because it runs immediately. Use an arrow wrapper: () => fn(arg) or fn.bind(null, arg).
Q2.1: Why does passing handleClick() to onclick execute immediately?
Conceptual
Explain why button.onclick = handleClick() does not wait for a user click.
Reveal Answer
When JavaScript parses the line button.onclick = handleClick(), the parentheses () cause the function to execute right then and there during script evaluation. Whatever handleClick() returns (usually undefined) is assigned to onclick. When the user clicks the button later, the browser tries to invoke undefined(), which does nothing.
Q2.2: Passing Function Reference vs Passing Return Value
Output
What will be printed?
function getGreeting() {
  return "Hello!";
}

function run(task) {
  console.log("Type:", typeof task);
  if (typeof task === "function") {
    console.log("Result:", task());
  } else {
    console.log("Direct value:", task);
  }
}

run(getGreeting);
run(getGreeting());
Reveal Output
Type: function Result: Hello! Type: string Direct value: Hello!
In the first call, getGreeting is a reference to the function. Inside run, task() invokes it. In the second call, getGreeting() runs first and evaluates to the string "Hello!", which is received by run as a string.
Q2.3: Lost "this" Context on Method Reference Extraction
Tricky Output
What will be printed when fn() is called?
const user = {
  name: "Sarah",
  getName() {
    return this.name;
  }
};

const fn = user.getName;
console.log(fn());
Reveal Output & Explanation
undefined
When user.getName is assigned to fn, only the function reference is copied, completely disconnecting it from the user object. When fn() is invoked as a standalone function, its this defaults to the global window object (or undefined in strict mode). Since window.name is not set, it returns undefined.
Fix: const fn = user.getName.bind(user);
Q2.4: Higher-Order Function Returning a Function Reference
Output
What will be printed by the following code?
function multiplier(factor) {
  return function(number) {
    return number * factor;
  };
}

const double = multiplier(2);
console.log(typeof double);
console.log(double(5));
Reveal Output
function 10
multiplier(2) returns an inner function reference where factor = 2 is captured by closure. The returned reference is stored in double. Calling double(5) runs the inner function: 5 * 2 = 10.
Q2.5: Passing Arguments into Callbacks: Arrow Function vs Function Reference
Best Practice
Which of the following three event listener setups is correct to pass the user ID 42, and why?
// Option A:
btn.addEventListener("click", deleteItem(42));

// Option B:
btn.addEventListener("click", function() { deleteItem(42); });

// Option C:
btn.addEventListener("click", () => deleteItem(42));
Reveal Answer
Options B and C are correct. Option A is a bug:
  • Option A: Invokes deleteItem(42) immediately on script run.
  • Option B & C: Pass an anonymous function reference that will only execute when the click event occurs. Option C is the modern, preferred ES6 concise syntax.

3. Objects and JSON Basics

Objects & JSON

⚡ Quick Revision Notes

  • JavaScript Object: An in-memory collection of key-value pairs. Can store methods, dates, undefined, and symbols.
  • JSON: Plain text data format used for transmission. Keys must be double-quoted. Values can only be strings, numbers, booleans, null, arrays, and objects.
  • Property Access: Dot notation (obj.prop) for fixed valid identifiers. Bracket notation (obj[varKey]) for dynamic variables or keys with special characters.
Q3.1: What are the main differences between a JavaScript Object and JSON?
Conceptual
Summarize the 3 core differences between a live JS object and a JSON string.
Reveal Answer
  1. Data Type: A JS Object is a live reference data structure stored in memory; JSON is a serialized string format.
  2. Allowed Types: JS Objects can hold functions, methods, undefined, and Symbol. JSON strictly forbids functions and undefined.
  3. Key Formatting: JS Objects allow unquoted keys (e.g. { age: 25 }); JSON requires double quotes around every key (e.g. { "age": 25 }).
Q3.2: Dynamic Keys: Dot Notation vs Bracket Notation
Output
What will be printed?
const field = "score";
const player = {
  score: 100,
  field: 50
};

console.log(player.field);
console.log(player[field]);
Reveal Output
50 100
player.field accesses the literal property named "field" → 50. player[field] evaluates the variable field (which holds "score") and reads player["score"] → 100.
Q3.3: Mutating a const Object
Tricky Output
Which of these lines will throw an error and why?
const car = { brand: "Toyota" };

car.brand = "Honda"; // Line A
car.year = 2024;     // Line B
car = { brand: "BMW" }; // Line C
Reveal Answer
Only Line C throws an error (TypeError: Assignment to constant variable).
const prevents the variable identifier car from being reassigned to a new memory address. It does not make the object itself immutable. Properties inside the object can still be added, modified, or deleted (Lines A and B work fine).
Q3.4: Checking Property Existence: in vs hasOwnProperty vs undefined
Output
What will each check print for this object?
const user = {
  role: undefined
};

console.log(user.role !== undefined);
console.log("role" in user);
console.log(user.hasOwnProperty("role"));
Reveal Output & Explanation
false true true
user.role !== undefined is false because the property exists, but its value is literally undefined! Both "role" in user and user.hasOwnProperty("role") correctly detect that the property key exists on the object, regardless of its value.
Q3.5: Keys with Special Characters and Hyphens
Syntax Rules
Why does user.first-name cause an error, and how must you write it?
Reveal Answer
In dot notation, JavaScript interprets the hyphen - as the subtraction arithmetic operator: user.first - name. It tries to subtract the variable name from user.first, resulting in ReferenceError: name is not defined or NaN.
Solution: Wrap the property name in quotes and use bracket notation: user["first-name"].

4. Variable and Function Hoisting

Hoisting & Scopes

⚡ Quick Revision Notes

  • Creation Phase: Before execution, the engine allocates memory for declarations.
  • var: Hoisted and initialized with undefined.
  • Function Declarations: Fully hoisted along with their complete function bodies.
  • Precedence: Function declarations hoist before variable declarations.
Q4.1: Why can we call a function before its declaration line?
Conceptual
Explain what the engine does during the compilation phase for a Function Declaration.
Reveal Answer
During the Creation Phase of the Execution Context, the engine scans the code and stores all Function Declarations in memory with their complete implementation. By the time the Execution Phase begins at line 1, the function already exists and is fully callable anywhere within its scope.
Q4.2: Function Declaration Overriding Var Declaration
Output / High Frequency
Predict the console output:
console.log(typeof greet);

var greet = "Welcome";

function greet() {
  return "Hello!";
}

console.log(typeof greet);
Reveal Output
function string
1. In the creation phase, function greet() hoists first. The declaration var greet; is ignored because greet already exists in scope.
2. Line 1: typeof greet is "function".
3. Line 3: greet = "Welcome" runs during execution, reassigning greet to a string.
4. Line 9: typeof greet is now "string".
Q4.3: Unassigned Var Following a Function Declaration
Tricky Output
What will be logged?
function score() {
  return 100;
}
var score;

console.log(typeof score);
console.log(score);
Reveal Output & Reason
function [Function: score]
var score; is only an unassigned declaration without an assignment expression. Because the identifier score was already bound to the function during the creation phase, the empty declaration var score; does not overwrite or reset it to undefined.
Q4.4: Nested Hoisting in Functions
Output
What will be logged by calling test()?
var a = 1;

function test() {
  console.log("a is:", a);
  var a = 2;
  console.log("a is now:", a);
}

test();
console.log("Global a:", a);
Reveal Output
a is: undefined a is now: 2 Global a: 1
Inside test(), var a is hoisted locally to the top of test as undefined, shadowing the outer global a = 1. The first log inside test sees local a before assignment → undefined. The global a remains 1.
Q4.5: Multiple var Declarations Interleaved
Tricky Output
What is the output?
var x = 10;
var x = 20;
var x;

console.log(x);
Reveal Output
20
JavaScript allows re-declaring variables with var without error. The third line var x; has no assignment, so it does nothing. x retains its last assigned value: 20.

5. Temporal Dead Zone (TDZ)

ES6 Scoping

⚡ Quick Revision Notes

  • Definition: The zone from the start of a block scope until the line where let or const is initialized.
  • Are let/const hoisted? YES. They are hoisted to the top of their block, but remain in an uninitialized state.
  • Accessing TDZ: Reading or writing to an uninitialized variable throws a ReferenceError: Cannot access 'x' before initialization.
  • typeof is NOT safe in TDZ: Calling typeof on a variable in TDZ also throws a ReferenceError!
Q5.1: Why is it called "Temporal" Dead Zone?
Conceptual
Why does the specification use the word "Temporal" (time-based) instead of "Spatial" (line-based)?
Reveal Answer
Because TDZ is determined by order of execution in time, not physical placement in code lines: 
function test() {
  const read = () => console.log(x); // Declared above let x physically!

  // Calling read() here would throw ReferenceError!
  let x = 42; 
  read(); // Works! Called after x has initialized in time.
}
test(); // Output: 42
Q5.2: Shadowing & TDZ in Block Scope
Output
What happens when this function is called?
let value = "global";

function show() {
  console.log(value);
  let value = "local";
}

show();
Reveal Output
ReferenceError: Cannot access 'value' before initialization
The declaration let value = "local" inside show() is hoisted to the top of show(). This places value in the TDZ for that local scope. When console.log(value) runs, the engine sees the uninitialized local binding and throws a ReferenceError immediately without checking outer scopes.
Q5.3: Default Function Parameter Evaluation Order TDZ
Tricky Output
What happens when calling fnA() vs fnB()?
function fnA(a = 1, b = a) {
  return a + b;
}

function fnB(a = b, b = 2) {
  return a + b;
}

console.log(fnA());
console.log(fnB());
Reveal Output & Explanation
2 ReferenceError: Cannot access 'b' before initialization
Function parameters evaluate left-to-right in their own parameter scope:
  • In fnA: a initializes to 1. Then b evaluates a (already initialized) → 1 + 1 = 2.
  • In fnB: a tries to evaluate b, but b is declared second and is still in its TDZ → throws ReferenceError.
Q5.4: typeof on TDZ vs Undeclared Variable
Tricky Edge Case
Compare what happens in both console logs:
console.log(typeof notDeclared);

{
  console.log(typeof myLet);
  let myLet = 10;
}
Reveal Output
undefined ReferenceError: Cannot access 'myLet' before initialization
While typeof on a totally missing variable safely returns "undefined", inside a TDZ typeof throws a ReferenceError!
Q5.5: let in a Switch Statement TDZ Collision
Tricky Output
What error occurs in this switch block?
const action = "create";

switch (action) {
  case "create":
    let message = "Item created";
    console.log(message);
    break;
  case "delete":
    let message = "Item deleted"; // Error here!
    console.log(message);
    break;
}
Reveal Answer & Fix
SyntaxError: Identifier 'message' has already been declared.
The entire switch body shares a single block scope! Both cases declare let message in the same block.
Fix: Wrap each case in its own block braces: 
case "create": {
  let message = "Item created";
  break;
}
case "delete": {
  let message = "Item deleted";
  break;
}

6. var and Function Expressions

Expressions vs Declarations

⚡ Quick Revision Notes

  • Function Declaration: function foo() {} — hoisted with its full body.
  • Function Expression: var foo = function() {} — the variable foo hoists as undefined.
  • Named Function Expression (NFE): var foo = function bar() {} — the name bar is scoped exclusively inside its own body (useful for recursion).
Q6.1: Why does invoking a var function expression early cause TypeError?
Conceptual
Why does foo() throw TypeError: foo is not a function instead of ReferenceError?
Reveal Answer
Because var foo is hoisted and initialized to undefined. The identifier foo exists in scope, so there is no ReferenceError. However, attempting foo() tries to execute undefined(). Since undefined is not a callable function, the engine throws a TypeError.
Q6.2: Calling Function Declaration vs Expression Before Definition
Output
What will be the output?
runA();
runB();

function runA() {
  console.log("Run A executed");
}

var runB = function() {
  console.log("Run B executed");
};
Reveal Output
Run A executed TypeError: runB is not a function
runA is fully hoisted and runs successfully. runB is hoisted as undefined. Calling runB() throws a TypeError and stops the script.
Q6.3: Named Function Expression Internal Scope
Tricky Output
What will be printed?
var calculate = function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
};

console.log(calculate(3));
console.log(typeof factorial);
Reveal Output
6 undefined
In a Named Function Expression, the function's internal name (factorial) is bound only inside the function's own body. Outside the function, factorial is not accessible in outer scope → typeof factorial === "undefined".
Q6.4: Function Expression Assigned to let vs var
Output
What error is thrown when calling start() early?
start();

let start = function() {
  console.log("Started");
};
Reveal Output
ReferenceError: Cannot access 'start' before initialization
Because start is declared with let, it is in the Temporal Dead Zone before line 3. Calling it early throws ReferenceError (unlike var, which throws TypeError).
Q6.5: When should you prefer a Function Expression over a Declaration?
Best Practice
List 2 practical situations where function expressions are preferred.
Reveal Answer
  1. Conditional Assignments: Assigning different functions based on runtime conditions (e.g. const handler = isMobile ? mobileFn : desktopFn;).
  2. Inline Callbacks: Passing anonymous or arrow functions directly into array methods: numbers.map(x => x * 2).

7. Hoisting-Based Output Questions

Tricky Edge Cases
Q7.1: The setTimeout in Loop Trap: var vs let
High Frequency
Explain the exact difference in output between Loop A and Loop B:
// Loop A:
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var i:", i), 50);
}

// Loop B:
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let j:", j), 50);
}
Reveal Output & Explanation
var i: 3 var i: 3 var i: 3 let j: 0 let j: 1 let j: 2
  • var i is function/global scoped. There is only one variable i in memory. By the time the 50ms timers execute from the Callback Queue, the synchronous loop has finished and i is 3. All 3 callbacks log 3.
  • let j is block scoped. For each iteration of the loop, a fresh binding of j is created. Each callback captures its iteration's value (0, 1, 2).
Q7.2: Chained Assignment Implicit Global Leakage
Tricky Output
What will be logged by the following code?
(function() {
  var a = b = 50;
})();

console.log(typeof a);
console.log(typeof b);
console.log(b);
Reveal Output & Reason
undefined number 50
var a = b = 50; is evaluated right-to-left:
1. b = 50: Without var, let, or const, b leaks into the global object (window.b = 50).
2. var a = b: Declares a locally inside the function.
3. Outside the function, a is not accessible (→ undefined), but b is accessible globally (→ 50).
Q7.3: Function Parameter vs Local Variable Hoisting
Tricky Output
What will be logged?
function test(x) {
  console.log("1:", x);
  var x = 20;
  console.log("2:", x);
}

test(10);
Reveal Output
1: 10 2: 20
Function parameters are initialized at the start of the function execution with their argument values (x = 10). The local declaration var x; inside the function does not overwrite the already-assigned parameter x. So line 1 prints 10. Then x = 20 assigns the new value, so line 2 prints 20.
Q7.4: Function Declaration Inside Dead if Branch
Tricky Output
What will be printed?
var flag = 1;

function process() {
  flag = 10;
  return;
  function flag() {}
}

process();
console.log(flag);
Reveal Output
1
function flag() {} is hoisted to the top of process(), creating a local variable flag inside process. When flag = 10 executes, it modifies the local flag. The global variable flag remains untouched at 1.
Q7.5: Fixing the var Loop with IIFE (Closure)
Solution Technique
How did developers solve the var loop closure problem before ES6 let existed?
Reveal Code Solution
By wrapping the inside of the loop in an Immediately Invoked Function Expression (IIFE) to lock each iteration's value in a new function scope: 
for (var i = 0; i < 3; i++) {
  (function(index) {
    setTimeout(() => console.log("iife:", index), 50);
  })(i);
}
// Output: 0, 1, 2
Q7.6: Illegal Shadowing in the Same Block
Compilation Error
What happens when this snippet runs?
let score = 50;
{
  var score = 100;
}
Reveal Output
SyntaxError: Identifier 'score' has already been declared
var ignores block boundaries and attempts to hoist to the outer scope. However, the outer scope already has let score declared in the same scope namespace. The engine detects this during compilation and throws a SyntaxError before running any code.

8. map() vs. filter()

Array Methods

⚡ Quick Revision Notes

  • map(): Transforms each item. Returns a new array with the exact same length as the input array.
  • filter(): Tests each item. Returns a new array containing only items that return truthy (length ≤ original).
  • Immutability: Neither method mutates the original array. Both return a new array.
Q8.1: Can map() ever return an array with fewer items than the original?
Conceptual
What happens if a developer does not return anything inside a map() callback?
Reveal Answer
NO. map() always returns an array of the exact same length. If the callback returns nothing (or returns undefined/null), the element at that index becomes undefined. It is never excluded.
Q8.2: Misusing map() to Filter Items
Output
What will be printed?
const nums = [1, 2, 3, 4, 5];

const result = nums.map(n => {
  if (n > 3) return n;
});

console.log(result);
Reveal Output
[ undefined, undefined, undefined, 4, 5 ]
For numbers 1, 2, and 3, the if condition is false and nothing is returned. JavaScript functions return undefined by default when no return statement executes.
Q8.3: The Classic ['1', '7', '11'].map(parseInt) Trap
High Frequency
Why does ['1', '7', '11'].map(parseInt) produce unexpected output?
Reveal Output & Reason
[ 1, NaN, 3 ]
map passes 3 arguments to its callback: (element, index, array). parseInt accepts 2 arguments: (string, radix).
  1. parseInt('1', 0): Radix 0 defaults to decimal base 10 → 1.
  2. parseInt('7', 1): Radix 1 is mathematically invalid → NaN.
  3. parseInt('11', 2): Radix 2 (binary) parses '11' as 1 × 21 + 1 × 20 → 3.
The Fix: ['1', '7', '11'].map(Number) or ['1', '7', '11'].map(n => parseInt(n, 10)).
Q8.4: Filtering Falsy Values
Output
What will be logged by passing Boolean to filter?
const mixed = [0, "hello", "", false, 42, null, undefined];
const clean = mixed.filter(Boolean);

console.log(clean);
Reveal Output
[ 'hello', 42 ]
filter(Boolean) passes each item into the Boolean() constructor. Falsy values (`0`, `""`, `false`, `null`, `undefined`, `NaN`) are dropped, leaving only truthy values.
Q8.5: Mutating Object References Inside map()
Tricky Output
Did map() preserve immutability here?
const list = [{ task: "Study", done: false }];

const updated = list.map(item => {
  item.done = true;
  return item;
});

console.log(list[0].done);
console.log(list === updated);
Reveal Output
true false
While updated is a new array (list !== updated), modifying item.done = true directly mutates the shared underlying object reference in memory!
Pure Pattern: list.map(item => ({ ...item, done: true })).
Q8.6: Sparse Array Holes in map vs filter
Tricky Output
What will be the lengths of both arrays?
const sparse = [1, , 3]; // Index 1 is empty

const m = sparse.map(x => x * 2);
const f = sparse.filter(x => true);

console.log(m.length, m);
console.log(f.length, f);
Reveal Output
3 [ 2, <1 empty item>, 6 ] 2 [ 1, 3 ]
map() preserves empty slots (holes) in the returned array, keeping length 3. filter() skips empty unassigned slots and removes them, reducing length to 2.

9. Shallow Copy vs. Deep Copy

Memory & Objects

⚡ Quick Revision Notes

  • Primitives: Copied by value (numbers, strings, booleans).
  • Objects & Arrays: Copied by reference (pointer in memory).
  • Shallow Copy: Clones only the top level. Nested objects are still shared: { ...obj }, Object.assign({}, obj), arr.slice().
  • Deep Copy: Duplicates every level into new memory: structuredClone(obj) (modern standard) or JSON.parse(JSON.stringify(obj)).
Q9.1: What is the main danger of using a shallow copy?
Conceptual
Explain what happens when modifying nested properties of an object cloned via the spread operator.
Reveal Answer
The spread operator { ...obj } only duplicates the top-level keys. If obj contains nested objects (like user.address.city), both the copy and the original hold a reference pointing to the exact same nested address object in memory. Changing copy.address.city will unintentionally alter the original object.
Q9.2: Shallow Copy Mutation Output Trace
Output
What will be printed?
const original = {
  title: "Guide",
  author: { name: "Alex" }
};

const copy = { ...original };
copy.title = "New Guide";
copy.author.name = "Bob";

console.log(original.title);
console.log(original.author.name);
Reveal Output
Guide Bob
copy.title is a primitive string at the top level → changing it does not affect original.title. copy.author is a shared object reference → changing copy.author.name directly modifies original.author.name.
Q9.3: Cloning an Array of Objects with Spread
Tricky Output
What will be logged?
const teamA = [{ name: "Dan" }];
const teamB = [...teamA];

teamB[0].name = "Eric";
teamB.push({ name: "Frank" });

console.log(teamA[0].name);
console.log(teamA.length);
console.log(teamB.length);
Reveal Output
Eric 1 2
[...teamA] creates a new outer array, so pushing to teamB does not change teamA.length. However, index 0 of both arrays references the identical player object. Mutating teamB[0].name affects teamA[0].name.
Q9.4: What are the practical limitations of structuredClone()?
Modern API
What types cannot be cloned with structuredClone()?
Reveal Answer
structuredClone() is built into modern browsers and handles Dates, RegExps, Maps, Sets, and circular references.
Limitations: It throws a DOMException if you try to clone functions (methods) or DOM elements.

10. Comparing Objects

Equality & Memory

⚡ Quick Revision Notes

  • Reference Equality: Objects and arrays are compared by their memory pointer, never by their properties.
  • {} === {} is always false.
  • a === b is only true if both point to the exact same object reference in memory.
Q10.1: Why does {} === {} evaluate to false?
Conceptual
Explain what the engine does when comparing two empty object literals.
Reveal Answer
Every time the JavaScript engine encounters an object literal {}, it allocates a brand-new, unique memory space in the Heap. The strict equality operator === checks whether both operands point to the exact same memory address. Since they reside at different memory locations, the comparison evaluates to false.
Q10.2: Array and Object Reference Equality
Output
Predict the boolean result of each line:

const b = [1, 2];
const c = a;

console.log(a === b);
console.log(a === c);
console.log({} == {});
Reveal Output
false true false
a === b: Separate array instances → false. a === c: Both variables point to the same memory location → true. {} == {}: Even with loose equality ==, distinct object references are never equal → false.
Q10.3: Object Reassignment and Reference Equality
Tricky Output
What will be logged?
let user1 = { name: "Tom" };
let user2 = user1;

user1 = { name: "Jerry" };

console.log(user2.name);
console.log(user1 === user2);
Reveal Output
Tom false
Initially, user2 points to the { name: "Tom" } object. Then, user1 = { name: "Jerry" } reassigns user1 to point to a brand-new object. user2 continues pointing to the original object ("Tom"). They are no longer the same reference → false.
Q10.4: The Coercion Equality Traps: [] == ![] and [] == 0
Tricky Edge Case
What are the outputs of these two loose equality checks?

console.log([] == 0);
Reveal Output & Reason
true true
1. [] == ![]: An empty array is truthy, so ![] evaluates to boolean false. The comparison becomes [] == false. false is converted to number 0. [] is converted to string "", which is then converted to number 0. 0 == 0 is true!
2. [] == 0: [].toString() is "". Number("") is 0. 0 == 0 is true!
Q10.5: How to Compare Two Objects by Value (Shallow Equal)
Implementation
Write a clean helper function to test if two flat objects have identical properties:
Reveal Code 
function areObjectsEqual(obj1, obj2) {
  const keys1 = Object.keys(obj1);
  const keys2 = Object.keys(obj2);

  if (keys1.length !== keys2.length) return false;

  for (let key of keys1) {
    if (obj1[key] !== obj2[key]) {
      return false;
    }
  }
  return true;
}

console.log(areObjectsEqual({ a: 1, b: 2 }, { a: 1, b: 2 })); // true
console.log(areObjectsEqual({ a: 1 }, { a: 2 })); // false

12. JSON (Parse, Stringify & Practical Gotchas)

JSON

⚡ Quick Revision Notes

  • JSON.stringify(data): Converts a JS object/array into a JSON string.
  • JSON.parse(str): Parses a valid JSON string back into a JS object/array. Throws a SyntaxError if malformed.
  • What gets omitted: Object keys with undefined or functions are silently dropped.
  • Inside Arrays: undefined and functions are converted to null.
Q12.1: What data types are lost when serializing to JSON?
Conceptual
What happens to functions, undefined, and Date objects during JSON.stringify()?
Reveal Answer
  • Functions and undefined: Omitted when they are object properties; converted to null inside arrays.
  • Date objects: Converted to ISO date strings (e.g. "2026-10-29T12:00:00.000Z"). When parsed back with JSON.parse(), they remain plain strings, NOT Date objects.
  • NaN and Infinity: Converted to null.
Q12.2: JSON.stringify() with Functions, Undefined and Arrays
Output
What will be the output string?
const account = {
  id: 101,
  balance: undefined,
  calcInterest: function() { return 5; },
  transactions: [100, undefined, 250]
};

console.log(JSON.stringify(account));
Reveal Output
{"id":101,"transactions":[100,null,250]}
balance and calcInterest are completely stripped from the object. Inside transactions, undefined is turned into null to keep the 2nd index occupied.
Q12.3: Circular Reference Error in JSON.stringify()
Tricky Exception
What happens when an object references itself?
const node = { id: 1 };
node.self = node;

JSON.stringify(node);
Reveal Output & Reason
TypeError: Converting circular structure to JSON
JSON format cannot represent circular or cyclic data structures. The serializer detects the loop and throws a TypeError to prevent infinite recursion.
Q12.4: How should you safely parse JSON from untrusted or network sources?
Best Practice
Why does JSON.parse() crash applications if not wrapped in try...catch?
Reveal Answer
If the input string is invalid JSON (e.g. trailing comma, single quotes, or empty response), JSON.parse() throws an unhandled SyntaxError that crashes your script.
Safe Pattern: 
function safeJSONParse(str, fallback = {}) {
  try {
    return JSON.parse(str);
  } catch (error) {
    console.error("Malformed JSON:", error.message);
    return fallback;
  }
}
Q12.5: Pretty-Printing JSON with Formatting Arguments
Output
What do the 2nd and 3rd arguments of JSON.stringify do?

console.log(JSON.stringify(data, null, 2));
Reveal Answer
  • 2nd argument (replacer): Can be an array of keys to whitelist or a filter function. Passing null includes all properties.
  • 3rd argument (space): Number of spaces for indentation (e.g. 2). It pretty-prints the JSON with line breaks and indentations for easy readability.

13. DOM and Browser Events

DOM Manipulation

⚡ Quick Revision Notes

  • DOM (Document Object Model): Tree of HTML elements representing the page structure.
  • Adding Listeners: element.addEventListener(type, handler). Allows attaching multiple listeners to the same event.
  • event.target: The exact innermost element that was clicked.
  • event.currentTarget: The element to which the event listener was attached.
Q13.1: event.target vs event.currentTarget
High Frequency
What is the critical difference between target and currentTarget?
Reveal Answer
  • event.target: The element that triggered the event (the origin, e.g. the innermost icon or span clicked).
  • event.currentTarget: The element that is currently handling the event (the element where addEventListener was registered). Inside non-arrow functions, event.currentTarget === this.
Q13.2: Target vs CurrentTarget on Nested Elements
Output

The click directly hit the <i> element (→ target: I). The listener was registered on the <button> (→ currentTarget: BUTTON).
Q13.3: Why removeEventListener Fails with Anonymous Functions
Common Trap
Why does this code fail to remove the event listener?
btn.addEventListener("click", () => console.log("Clicked!"));
btn.removeEventListener("click", () => console.log("Clicked!"));
Reveal Answer & Fix
() => ... creates a brand-new function reference in memory each time it is written! removeEventListener requires the exact same function reference that was passed to addEventListener.
Fix:

  console.log("Clicked!");
}

Q13.4: onclick property vs addEventListener()
Conceptual
What happens if you assign two handlers using element.onclick vs element.addEventListener?
Reveal Answer
  • element.onclick = fn1; element.onclick = fn2;: The second assignment overwrites the first. Only fn2 runs.
  • element.addEventListener('click', fn1); element.addEventListener('click', fn2);: Both listeners are registered and both will run when clicked.

In standard functions (Handler A), the browser sets this to the element that fired the listener (the button). Arrow functions (Handler B) do NOT have their own this; they retain the lexical this from the surrounding scope (usually window).

14. Event Bubbling & Delegation

DOM Events

⚡ Quick Revision Notes

  • Event Bubbling: When an event triggers on an element, it first runs on that element, then bubbles up through its parents up to document and window.
  • Event Delegation: Attaching a single listener to a common parent element to handle events for all current and future child elements.
  • Events that do NOT bubble: focus, blur, mouseenter, mouseleave.
Q14.1: What is Event Delegation and why is it a best practice?
High Frequency
Explain how Event Delegation works and its 2 major advantages.
Reveal Answer
Event Delegation leverages Event Bubbling: instead of attaching 100 listeners to 100 <li> items, you attach one listener to the parent <ul>.
Two Advantages:
  1. Memory Optimization: Only 1 event listener function is allocated in memory.
  2. Dynamic Elements: If new list items are added dynamically via JavaScript later, they automatically have click functionality without needing new listeners!
Q14.2: Execution Order in Event Bubbling
Output

  console.log("Parent clicked");
});

document.getElementById("child").addEventListener("click", () => {
  console.log("Child clicked");
});
Reveal Output
Child clicked Parent clicked
Due to Event Bubbling, the event triggers first on the target element (child), then bubbles up to its parent element (parent).
Q14.3: Event Delegation with Nested Child Elements (closest method)
Practical Implementation
If a button contains an icon: <button class="del-btn"><i>🗑️</i> Delete</button>, clicking the icon makes e.target the <i> tag. How do you reliably find the button?
Reveal Solution Code

    console.log("Delete button clicked!");
  }
});
Q14.4: What are the 3 Phases of Event Propagation?
Conceptual
Name the three phases and explain how to listen in the Capturing phase.
Reveal Answer
  1. Capturing Phase: Event travels down from window → document → ancestors down to the target.
  2. Target Phase: Event reaches the clicked target element.
  3. Bubbling Phase: Event travels up from target element back up to window.
By default, listeners run in the Bubbling phase. To listen in Capturing phase, pass true as the 3rd argument: element.addEventListener('click', handler, true).
Q14.5: Name Events that Do NOT Bubble
Edge Case
Why does event delegation fail on focus and mouseenter? What are their bubbling alternatives?
Reveal Answer
focus, blur, mouseenter, and mouseleave do not bubble up the DOM tree.
Bubbling Alternatives:
  • For focus / blur → use focusin and focusout (which bubble!).
  • For mouseenter / mouseleave → use mouseover and mouseout (which bubble!).

15. stopPropagation() vs. preventDefault()

Event Control

⚡ Quick Revision Notes

  • event.stopPropagation(): Stops the event from bubbling up to parent ancestors in the DOM tree.
  • event.preventDefault(): Cancels the browser's native default behavior (e.g. form submission refresh, link navigation).
  • Key Fact: They do completely different things! preventDefault() does NOT stop bubbling.
Q15.1: Does preventDefault() stop event bubbling?
High Frequency
What happens to parent listeners when a child calls e.preventDefault()?
Reveal Answer
NO! e.preventDefault() only stops native browser actions (like following an <a> link or reloading on form submit). The event still bubbles up to parent elements and triggers their listeners. To stop bubbling, you must call e.stopPropagation().

16. AJAX

Async Network

⚡ Quick Revision Notes

  • AJAX: Asynchronous JavaScript and XML. Updating parts of a web page dynamically in the background without refreshing the whole document.
  • Evolution: Originally built with XMLHttpRequest; modern applications use the fetch() API.
  • XHR readyStates: 0 (Unsent), 1 (Opened), 2 (Headers Received), 3 (Loading), 4 (Done).
Q16.1: What problem did AJAX solve in web development?
Conceptual
How does user experience differ between traditional web requests and AJAX requests?
Reveal Answer
In traditional web apps, every user interaction (like submitting a form or navigating pages) sent a request to the server, which returned an entire new HTML page. This caused a full screen refresh, losing scroll position and UI state.

AJAX requests small pieces of data (usually JSON) in the background and modifies only the necessary DOM elements, enabling fast, responsive single-page web applications.
Q16.2: What are the 5 readyStates of XMLHttpRequest?
XHR Basics
List the states from 0 to 4 in an XHR request lifecycle.
Reveal Answer
  • 0 (UNSENT): Client has been created, open() not called yet.
  • 1 (OPENED): open() has been called.
  • 2 (HEADERS_RECEIVED): send() called, headers and status are available.
  • 3 (LOADING): Downloading response body.
  • 4 (DONE): Operation complete.
Q16.3: Basic XMLHttpRequest Pattern
Implementation
Write a classic XHR GET request checking for successful completion:
Reveal Code 
const xhr = new XMLHttpRequest();
xhr.open("GET", "https://api.example.com/users", true);

xhr.onreadystatechange = function() {
  if (xhr.readyState === 4) { // DONE
    if (xhr.status === 200) {
      const data = JSON.parse(xhr.responseText);
      console.log("Success:", data);
    } else {
      console.error("HTTP Error:", xhr.status);
    }
  }
};

xhr.send();
Q16.4: Why was fetch() introduced to replace XMLHttpRequest?
Evolution
List 2 advantages of fetch() over XMLHttpRequest.
Reveal Answer
  1. Promise-based: fetch() returns Promises, avoiding callback nesting ("callback hell") and integrating cleanly with modern async/await.
  2. Cleaner API: Simpler request/response model with built-in streaming body parsers (.json(), .text(), .blob()).

17. fetch() Return Value & Behavior

Async & Fetch

⚡ Quick Revision Notes

  • Return Value: fetch(url) returns a Promise.
  • THE #1 INTERVIEW TRAP: fetch() DOES NOT REJECT on HTTP 404 or 500 status codes! It only rejects if there is a network disconnection, DNS failure, or request abort.
  • Check Status: Always check response.ok (boolean: true for 200-299) or response.status.
  • Body Stream: response.json() also returns a Promise and can only be read once.
Q17.1: Why does fetch() NOT reject on HTTP 404 or 500 errors?
High Frequency
Explain the design rationale behind Promise resolution in the Fetch API.
Reveal Answer
From a network perspective, receiving an HTTP 404 Not Found or 500 Server Error is still a completed, successful HTTP transaction: the browser connected to the server, sent headers, and received a valid HTTP response with a status code.

A Promise should only reject if the operation failed to complete at all (e.g. computer is offline, DNS failure, or request blocked by CORS).

Output
What will be logged when requesting a non-existent URL?

The `catch` block is never reached! The Promise resolves normally, and `res.ok` evaluates to `false` because status 404 is outside the 200–299 range.
Q17.3: Reading Response Body Twice (Stream Disturbed Error)
Tricky Output
What error happens when reading both .text() and .json() from the same response?

  const text = await res.text();
  const json = await res.json(); // What happens here?

The body of a Fetch Response is a readable stream. Once consumed by res.text(), the stream is exhausted.

Q17.4: Production-Safe fetch() Pattern with async/await

Write the standard, error-safe way to handle API requests using fetch():
Reveal Code 
async function fetchUserProfile(userId) {
  try {
    const response = await fetch(`https://api.example.com/users/${userId}`);

    // Must check response.ok manually!
    if (!response.ok) {
      throw new Error(`HTTP Error! Status: ${response.status}`);
    }

    const data = await response.json(); // Wait for body parsing
    return data;
  } catch (error) {
    console.error("Request failed:", error.message);
  }
}
Q17.5: Unexpected HTML Response Parsing Error
Real-World Trap
Why does response.json() throw SyntaxError: Unexpected token '<', " when an API fails?
Reveal Answer
When a web server crashes or returns an error page (like a 502 Bad Gateway or 404 page), it often returns an HTML error document starting with <!DOCTYPE html> instead of JSON data. Attempting to parse that HTML string with response.json() fails because the first character < is not valid JSON. Checking response.ok before calling .json() prevents this!
